# Samuel · מערכת ניהול

מערכת ניהול פנימית לעסק התכשיטים — הזמנות, לקוחות ותמחור.
רצה **מקומית לגמרי** על המחשב, בלי ענן ובלי חיבור לאינטרנט.

אלה **שלבים 1–5** מתוך תוכנית הבנייה שבמסמך התכנון (`../docs/jewelry-crm-spec.md`).

## מה יש כאן

- **כניסה בסיסמה** — משתמש יחיד, כל המערכת מאחורי הגנה.
- **לקוחות** — פרטי / חנות / מפיץ, דרכי קשר, מקור הגעה, דגל ייצוא, יומן.
- **הזמנות** — סוג, ערוץ, דחיפות, שלושה תאריכים (אירוע / מובטח / יעד פנימי).
- **פריטי הזמנה עם מנוע התמחור** — כרטיס הפריט של *מאזני תמחור*, שדה בשדה,
  עם חישוב עלות ומחיר **בזמן ההקלדה**.
- **מע״מ מול ייצוא** — דגל בהזמנה שמאפס מע״מ אוטומטית.
- **צילום שערים** — כל הזמנה נועלת את שער הזהב, הדולר והמע״מ של יום פתיחתה.
- **מסלול סטטוסים** מפנייה עד סגור, עם רישום כל מעבר ותאריכו.
- **דשבורד** — מסירות השבוע, איחורים, משימות קרובות, צנרת, שערי היום.
- **משימות ויומן** — ברמת הזמנה, לקוח, או כלליות.
- **קטלוג דגמים עם תמונות** — מפרט, תמחור, וגלריה. התמונות מוקטנות בדפדפן
  ל-1600px ונשמרות **בתוך `jewelry.db`**, כך שהגיבוי נשאר קובץ אחד.

### לולאת הקטלוג

הקטלוג לא דורש הכנה מראש — הוא נבנה מהעבודה עצמה:

1. אתה מתמחר פריט בהזמנה כרגיל.
2. לוחץ **״שמור כדגם״** — המפרט והתמחור עוברים לקטלוג, והפריט נקשר לדגם.
3. בהזמנה הבאה בוחרים את הדגם מהרשימה ו**כל השדות נטענים** — ומחשבים מחדש
   לפי שערי אותה הזמנה.
4. תמונות מוסיפים אחרי המסירה, כשיש צילום.

- **עמודי שיתוף** — דגם מפורסם מקבל לינק קבוע `/p/[slug]`, וקולקציה מקבלת
  `/c/[slug]`. עמוד נקי עם גלריה, מפרט, מחיר (או ״לפנייה״) וכפתור וואטסאפ.
- **תשלומים וגבייה** — מקדמה, ביניים, סופי והחזר. כל תשלום נשמר במטבע שבו
  התקבל עם השער של אותו יום, ומספר החשבונית מחשבונית ירוקה נשמר כאסמכתא.
  מסך גבייה מרכז את כל היתרות הפתוחות לפי גיל.

## התקנה והרצה

```bash
pnpm install
pnpm db:migrate                        # יוצר jewelry.db וכל הטבלאות
node scripts/seed.mjs you@email סיסמה   # יוצר את המשתמש שלך
pnpm dev
```

פתח `http://localhost:3000`.

להרצה במצב production מקומי:

```bash
pnpm build && pnpm start
```

### שינוי סיסמה

```bash
node scripts/seed.mjs you@email סיסמה-חדשה
```

### סוד חתימת הסשן

```bash
pnpm setup:secret
```

יוצר `APP_SECRET` אקראי ושומר ב-`.env.local`. הסוד חותם את עוגיית הסשן;
בלעדיו `pnpm start` **מסרב לעלות**, כי סוד שכתוב בקוד שווה לאין סוד.
בהרצת `pnpm dev` יש נפילה לסוד מקומי עם אזהרה.

### הגנה על הכניסה

אחרי 10 ניסיונות כושלים מאותה כתובת, הכניסה נחסמת לרבע שעה — כולל לסיסמה
הנכונה. המונה בזיכרון ומתאפס בהפעלה מחדש.

## מנוע התמחור

```
מחיר זהב לגרם ($) = ספוט לאונקיה ÷ 31.1034768 × (טוהר ÷ 999)

עלות = זהב + אבן מרכזית + אבני צד + מודל + עבודת צורף
       + שיבוץ מרכזית + שיבוץ צד + רודיום + קופסא + שקית + אריזה
מחיר = עלות × מכפיל          (או מחיר ידני שדורס אותו)
```

**מכפיל אינו שיעור רווח.** ×1.3 נותן 23% רווח ממחיר המכירה, ×2 נותן 50%.
המערכת מציגה את שני המספרים זה לצד זה במסך ההגדרות ובכל בחירת מכפיל.

**דולר הוא מטבע העלות** — זהב ואבנים מתומחרים בדולר. השקל הוא שכבת תצוגה,
מומר לפי השער שננעל על ההזמנה.

**יתרה לגבייה** = סה״כ ההזמנה פחות התשלומים, פחות החזרים. תשלום נשמר במטבע
שבו התקבל עם השער של יום התשלום, ולכן היתרה נכונה גם כשהשער זז בין תשלומים.
הסף ל״שולם במלואו״ נגזר ממטבע התצוגה — יתרה שמוצגת כ-₪0 נחשבת סגורה, כדי
שהזמנה לא תיתקע ברשימת הגבייה בגלל שברי אגורות.

## שיתוף — מה צריך כדי שזה יעבוד באמת

עמוד שיתוף הוא כתובת שהלקוח פותח בטלפון שלו. כל עוד המערכת רצה **רק על
המחשב שלך**, הלינק יעבוד רק מהמחשב הזה. כדי לשלוח לינק ללקוח צריך שהמערכת
תהיה נגישה מהאינטרנט — למשל דרך מנהרה (Cloudflare Tunnel, ngrok) או אחסון בענן.

```bash
# כתובת קבועה — הקמה חד-פעמית, מומלץ
pnpm setup:tunnel shop.הדומיין-שלך.com

# כתובת זמנית — לבדיקה מהירה בלי דומיין
pnpm tunnel
```

שניהם שומרים את הכתובת אוטומטית בהגדרות, וכל הלינקים ייבנו ממנה. הסלאג
עצמו לא משתנה, ולכן החלפת כתובת לא נוגעת בו.

תת-דומיין של דומיין קיים מספיק. התנאי היחיד: ה-DNS מנוהל ב-Cloudflare.

**המדריך המלא, כולל כתובת קבועה: [`docs/going-public.md`](docs/going-public.md).**

### מה פתוח ומה סגור

| כתובת | מי נכנס |
|---|---|
| `/p/[slug]` · `/c/[slug]` | כל אחד עם הלינק — **רק** לדגמים ולקולקציות שפורסמו |
| `/photos/[id]` | תמונה של דגם מפורסם — פתוחה. אחרת — דורשת סשן |
| כל השאר | רק אחרי כניסה בסיסמה |

הסלאג נוצר פעם אחת בפרסום ולא משתנה, כדי שלינק שכבר נשלח לא יישבר. ביטול
פרסום מחזיר 404 מיידית.

## גיבוי

כל המידע בקובץ אחד: `jewelry.db`.

```bash
cp jewelry.db "backups/jewelry-$(date +%Y%m%d).db"
```

## מה עוד לא נבנה

לפי תוכנית השלבים: ספקים ופורטל המפעל, עמוד לקוח, הוצאות ודוחות רווחיות.

## הערות טכניות

- **Node 22 ומעלה** — המערכת משתמשת ב-`node:sqlite` המובנה, בלי בינארי חיצוני.
- הפרויקט יושב כרגע בתוך ריפו של מערכת אחרת, ולכן יש בו `pnpm-workspace.yaml`
  משלו ו-`turbopack.root` מקובע. כשיעבור לריפו נפרד אפשר להשאיר את שניהם.
- הגופנים מוגשים מקומית מ-`public/fonts` — המערכת נראית נכון גם בלי אינטרנט.
  לספרות משמשת מחסנית מונו של המערכת; אם תרצה את IBM Plex Mono כמו במחשבון,
  הוסף את קובץ ה-woff2 ל-`public/fonts` והצהר עליו ב-`globals.css`.
